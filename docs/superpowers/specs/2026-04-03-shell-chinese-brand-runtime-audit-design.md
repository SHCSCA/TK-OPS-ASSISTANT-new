# 壳层中文化与品牌收口设计（含真实接入审计）

## 背景

当前壳层已具备新架构运行能力，但仍存在用户可见一致性问题：

- 品牌图形在顶部与启动页仍出现 `TK` 字母占位
- Runtime 在多个区域直接暴露英文状态码（如 `managed-runtime-detected`）
- 通知中心与状态弹层在窄屏下存在遮挡与可用性问题
- 左下角“当前阶段”仍为静态文案，与迁移矩阵不一致

同时，本轮要求对已迁移 8 页做“真实接入”收口，避免写死业务值与假数据感。

## 设计目标

1. 品牌图标统一，品牌文案保持 `TK-OPS`
2. Runtime 展示全链路中文化，界面不暴露英文状态码
3. 通知中心/运行状态弹层在 `960/860/760` 下可稳定使用
4. 阶段信息改为动态数据源，杜绝双口径
5. 已迁移 8 页保持真实接入与中性空态

## 设计方案

### 1) 品牌与图标统一

- 前端显示统一使用 `apps/desktop/public/tkops.ico`
- 顶部 `logo-mark` 改为真实 `<img>` 图标渲染
- `splash.html` 中间 logo 改为图标容器 + `<img>`
- 保留文本品牌 `TK-OPS`

### 2) Runtime 展示映射层

新增 `runtimePresentation` 模块，职责：

- `mapRuntimeStatus(raw)`：状态码 -> 中文文案 + tone
- `mapRuntimeLaunchMode(raw)`：启动模式 -> 中文文案
- `mapThemeMode(raw)`：主题值 -> `浅色/深色/跟随系统`

覆盖状态集合：

- `managed-*`
- `external-*`
- `browser-fallback`
- `unknown`
- `ok/ready/healthy` 等健康态

映射接入位置：

- 底栏 `statusLeftChips`
- 顶栏 `status-summary-panel`
- 右侧详情 `DetailPanel` 宿主/Runtime 摘要

### 3) 窄屏弹层可用性修复

对通知中心与状态弹层统一增强：

- 宽度上限：`min(固定宽, 视口宽)`
- 高度上限：基于视口计算 `max-height`
- 内容滚动：`overflow-y: auto`
- 层级提升：高于标题栏与主内容
- 小宽度下横向纠偏，避免被窗口边缘裁切

### 4) 当前阶段动态化

新增 `migrationProgress` 模块，从 `routeManifest` 推导：

- 已迁移数、总数、待迁移数、迁移比例
- 阶段标题/阶段描述
- 下一优先迁移页（按导航分组顺序 + 菜单顺序）

接入：

- `Sidebar.vue` 左下角阶段框
- `MigrationPlaceholderPage.vue` 当前阶段卡片

保证“一个数据源，多处展示”一致。

### 5) 8 页真实接入审计

审计原则：

- 页面主数据必须来自 runtime API / 宿主状态
- 表单默认值可保留，但业务指标不得写死
- 缺数据统一中性空态（`--`、`暂无数据`）

本轮修复点：

- `scheduler` 窗口信息回退从“具业务含义默认值”改为中性空态
- 增加静态契约测试，防止未来回归到英文状态码或静态阶段文案

## 风险与取舍

- Runtime 状态码可能继续扩展：映射层采用“显式映射 + 关键词兜底”，确保不会裸露英文码
- 弹层样式可能受旧壳 CSS 叠加影响：优先在新壳 `main.css` 做高优先级覆盖，必要时补 `components.css`
- 动态阶段文案可能随路由结构变化：通过 routeManifest 单点推导降低维护成本

## 完成标准

- 顶部 logo 与启动页 logo 均为图标渲染，不再出现 `TK` 字母块
- Runtime 在底栏/状态弹层/右侧详情均为中文展示
- `960/860/760` 下通知中心与状态弹层可完整查看和点击
- 左下角与占位页阶段信息均来自动态迁移数据
- 8 页链路通过审计，缺数据为中性空态，无假业务数字
